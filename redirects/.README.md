# Redirects site

The HTTPX2 docs used to be served from `httpx2.pydantic.dev` and now live at
<https://pydantic.dev/docs/httpx2/>.
This directory is deployed to `httpx2.pydantic.dev` in their place: a Cloudflare Worker (`httpx2-docs`, configured in
`wrangler.toml`) that serves no pages of its own, only the rules in `_redirects`.

Deploy it by hand after changing `_redirects`, there's no workflow for it:

```bash
wrangler deploy
```

Check rules locally first with `wrangler dev`, which prints how many it parsed and serves them on localhost.

Two behaviours differ between `wrangler dev` and production, both found by testing the deployed site:

- Splat rules such as `/advanced/*` lose to the `/*` catch-all in production, though they win locally.
  Every path we care about is therefore listed in full rather than matched by prefix.
- Redirect rules take precedence over static assets, so the catch-all shadows any file placed here.
  That includes `robots.txt`, which is why there isn't one.
  A `200` rewrite to serve it anyway works locally and is ignored in production.

This README is uploaded with the rest of the directory, and like any file here it is unreachable: a request for
`/.README.md` matches the catch-all and redirects.
